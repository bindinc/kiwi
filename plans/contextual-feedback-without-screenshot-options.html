Contextual feedback · UX decision artifact

Make the screenshot helpful, not mandatory.

Three interaction models for letting people submit useful KIWI feedback without first taking a screenshot. This artifact recommends a form-first flow while preserving screenshot capture as an easy, visible enhancement.

Recommendation: form first

Make the required comment the primary task and expose “Add screenshot” as an optional secondary action.

Recommended

Start with the user’s actual goal

The feedback form opens immediately. Screenshot capture is available without blocking people who only need to describe an issue or suggestion.

  • Lowest friction for text-only feedback.
  • Clear keyboard path with no pointer-only prerequisite.
  • One obvious primary action: “Send feedback”.
  • The optional screenshot remains discoverable beside the primary flow.

Trade-off: this changes today’s picker-first mental model and requires the dialog to pause and resume while capture mode is active.

Balanced

Make the branch explicit

A small chooser appears before either workflow begins. Both paths are equally visible and carry a short explanation.

  • No hidden or surprising alternate path.
  • Works well with keyboard and assistive technology.
  • Keeps the existing screenshot workflow largely intact.
  • Supports future attachment types without overloading the form.

Trade-off: every user pays for an extra decision and click, including frequent users who always take screenshots.

Smallest change

Add an escape hatch to the picker

The current picker still opens first. A persistent secondary action lets users leave capture mode and continue with a text-only report.

  • Smallest visual and technical change.
  • Fastest path remains unchanged for screenshot-first users.
  • The alternate path can be explained in the picker instructions.

Trade-off: text-only feedback still starts inside a pointer-oriented screenshot mode, making the flow feel secondary and less direct.

Decision matrix

Why form first is the strongest default

The screenshot is supporting evidence; the comment is the required feedback. The interface should reflect that hierarchy.

Criterion Form first Choice first Picker escape hatch
Text-only speed Best · no preliminary step Good · one explicit choice Fair · enter and leave picker
Screenshot speed Good · one secondary action Good · one explicit choice Best · current path
Accessibility Best · form controls first Good · accessible two-choice step Fair · pointer mode appears first
Clarity Best · optional means optional Good · branch is explicit Fair · skip path can be overlooked

API and validation

Make both screenshot multipart files optional as a pair. Keep the comment required and reject submissions containing only one privacy variant.

Storage and context

Allow reports with no screenshot rows and replace required element metadata with an explicit selection kind: none, element, or area.

Teams delivery

Omit the image and screenshot action when absent. Keep page, reporter, category, severity, and comment facts so text-only reports remain actionable.

Design basis

Accessibility and interaction principles

  • W3C WAI Forms Tutorial — label controls and explain expected input.
  • WCAG 2.2: On Input — keep changes of context predictable.
  • GOV.UK Button guidance — use one main call to action and style secondary actions accordingly.
  • GOV.UK Check answers pattern — represent skipped optional information explicitly.
